1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
CareSync is a full-stack Healthcare Clinic Management & Real-Time Queue System.
It streamlines clinic operations across three distinct user roles:
  - Patients: Search doctors, book physical/video appointments, view live queue
    position & estimated wait time, manage personal health records (prescriptions,
    lab reports, medical bills, past consultations).
  - Doctors: Manage personal clinic profiles, working hours, and consultation fees;
    run live clinic consultation workspaces (calling next patient, starting/ending
    consultations, writing notes/records); invite and manage receptionists.
  - Receptionists: Manage clinic queue desks for multiple assigned doctors, issue
    walk-in tokens, call and complete patient visits, reschedule appointments, and
    upload paper prescriptions, bills, and test reports.

Technology Stack:
  - Backend: Node.js, Express.js, MongoDB (Mongoose), Socket.IO (WebSockets),
    Cloudinary (Secure asset storage), Nodemailer (Email verification),
    Bcryptjs (Password & OTP hashing), JWT (HttpOnly Cookie-based authentication).
  - Frontend: React 19, Vite, Tailwind CSS, Redux Toolkit, React Router v7,
    Socket.IO Client, Lucide React / SVG icons.

--------------------------------------------------------------------------------
BACKEND ROOT & CONFIGURATION
--------------------------------------------------------------------------------
- backend/index.js
  Main server entry point. Configures Express app, CORS, fileUpload middleware,
  cookie-parser, and JSON parsers. Connects to MongoDB asynchronously before
  starting HTTP server. Initializes Socket.IO and mounts API routes under /api/v1.

- backend/package.json
  Backend project metadata and npm dependencies (express, mongoose, socket.io,
  jsonwebtoken, bcryptjs, cloudinary, express-fileupload, nodemailer, dotenv, cors).

- backend/config/database.js
  MongoDB connection utility using Mongoose. Returns a connection promise so
  index.js can await database readiness before serving requests.

- backend/config/cloudinary.js
  Configures Cloudinary v2 SDK using CLOUD_NAME, API_KEY, and API_SECRET from .env.

- backend/read.md
  Developer documentation covering server port settings and notes on auth routes.

--------------------------------------------------------------------------------
BACKEND MODELS (DATABASE SCHEMAS)
--------------------------------------------------------------------------------
- backend/models/baseUserFields.js
  Shared Mongoose schema plugin for all user types. Defines common fields:
  6-digit custom ID, fullName, email, password (hashed on save via bcrypt hook),
  phone, gender, profilePhoto, and timestamps.

- backend/models/Patient.js
  Patient schema extending baseUserFields. Contains dateOfBirth, bloodGroup,
  allergies, medicalHistory array, consultations array, prescriptions array,
  reports array, and bills array.

- backend/models/Doctor.js
  Doctor schema extending baseUserFields. Contains specialization, licenseNumber,
  consultationFee, clinicAddress (street, city, state, zip), workingHours schema,
  averageRating, totalRatings, and reviews array.

- backend/models/Receptionist.js
  Receptionist schema extending baseUserFields. Includes staffCode and associated
  clinic metadata.

- backend/models/Appointment.js
  Core queue and booking record. Stores doctor ref, optional patient ref, date (YYYY-MM-DD),
  tokenNumber, status ("waiting", "in_consultation", "completed", "cancelled", "no_show"),
  source ("online", "walk_in"), type ("physical", "video"), walkInDetails (name, phone, age, gender),
  paymentStatus, payment ref, and consultationId link.

- backend/models/Assignment.js
  Tracks Doctor <-> Receptionist workplace collaboration relationships and invitations
  (status: "pending", "accepted", "rejected").

- backend/models/DayCounter.js
  Atomic token numbering schema. Provides an auto-incrementing sequence counter
  per doctor per calendar date.

- backend/models/Payment.js
  Tracks appointment checkout payments. Stores patient, doctor, date, amount,
  currency, status ("created", "paid", "refunded"), provider ("demo"), and expiration.

- backend/models/Otp.js
  Schema for email verification OTPs. Stores email, bcrypt-hashed OTP, verified boolean,
  attempts counter (capped at 5 attempts), and MongoDB TTL index on expiresAt for auto-cleanup.

--------------------------------------------------------------------------------
BACKEND MIDDLEWARES
--------------------------------------------------------------------------------
- backend/middlewares/authMiddleware.js
  Authenticates requests using JWT from either the 'token' httpOnly cookie or
  the Authorization Bearer header. Populates req.user ({ accountId, role }).

- backend/middlewares/loadAccount.js
  Queries the appropriate database model based on req.user.role and attaches
  the active user account document to req.account.

- backend/middlewares/loadPatient.js
  Ensures that the authenticated user has the 'patient' role and attaches
  the Patient model document to req.patient.

- backend/middlewares/queueAccess.js
  Validates that the authenticated caller has permission to view or modify
  a specific doctor's queue (either the doctor themself or an assigned receptionist).

- backend/middlewares/resolveDoctor.js
  Resolves a doctor by 6-digit ID or MongoDB ObjectId from params/body and
  attaches the doctor document to req.doctor.

--------------------------------------------------------------------------------
BACKEND CONTROLLERS
--------------------------------------------------------------------------------
- backend/controllers/auth.js
  Handles role-based user registration (/register/:role). Enforces 6-digit role-specific
  ID prefix (1=patient, 2=receptionist, 3=doctor), verifies completed email OTP, auto-passes
  phone verification, applies whitelist field filtering against mass assignment, creates
  user with pre-save password hash, signs JWT, and sets httpOnly auth cookie.

- backend/controllers/login.js
  Authenticates user login with email/password against Patient, Doctor, or Receptionist
  collections. Checks bcrypt password match, signs JWT, sets auth cookie, and returns
  user profile without sensitive data.

- backend/controllers/logout.js
  Clears the httpOnly authentication cookie using matching security options (SameSite,
  Path, Secure flag in production) and returns logout confirmation.

- backend/controllers/googleauth.js
  Handles Google OAuth sign-in. Verifies Google ID token against Google's OAuth2 client,
  matches or provisions user account, signs session JWT, and returns authenticated payload.

- backend/controllers/auththroughcookie.js
  Endpoint for session re-hydration (/me or /auththroughcookie). Reads auth token
  from cookie, fetches fresh user profile from DB, and returns updated user slice data
  (including profilePhoto, role, and details).

- backend/controllers/sendotp.js
  Generates a cryptographically secure 6-digit OTP using crypto.randomInt, hashes
  it using bcrypt, saves to Otp collection with 5-minute expiry, and dispatches email
  via Nodemailer.

- backend/controllers/verifyotp.js
  Verifies submitted OTP against bcrypt hash stored in MongoDB. Tracks failed attempts
  (max 5 attempts lockout) and marks email as verified with a 15-minute registration window.

- backend/controllers/bookingController.js
  Patient appointment booking workflow:
  1) checkout: Validates doctor booking window/schedule, checks for duplicate active bookings,
     and creates/refreshes payment session.
  2) confirm: Validates payment status, creates appointment token atomically via queueService.
  3) list & cancel: Lists upcoming bookings for patient and handles appointment cancellations.

- backend/controllers/doctorSearchController.js
  Public doctor discovery API. Enables search by specialization, name, or city.
  Returns doctor cards with consultation fee, rating, clinic address, and next bookable dates.

- backend/controllers/queueController.js
  Queue desk and doctor consultation workspace API:
  - getQueue: Fetches current day's queue, now serving, and waiting list.
  - nextPatient: Advances queue atomically, moving current to completed and next to in_consultation.
  - completeVisit: Finishes consultation and triggers consultation record creation.
  - walkIn: Issues on-the-spot token for walk-in patients without requiring an online account.
  - reschedule & cancel: Reassigns or removes appointments from the active queue.

- backend/controllers/doctorController.js
  Manages doctor self-profile: updates biography, clinic address, facilities, consultation
  fee, and weekly working hours schedule.

- backend/controllers/doctorPatientController.js
  Enables consulting doctors to view patient history, allergies, past diagnoses, and
  attach consultation clinical notes.

- backend/controllers/patientController.js
  Patient profile management: update personal details, fetch consultations, and upload/view
  personal health files (prescriptions, test reports, and bills).

- backend/controllers/receptionistController.js
  Receptionist operations: view profile, query assigned doctors, accept doctor invitations,
  and request collaboration with doctors.

- backend/controllers/recordsController.js
  Enables receptionists to upload paper prescriptions, lab reports, and clinic invoices
  for a patient's visit. Stores files in Cloudinary authenticated storage and attaches
  records to the patient's consultation history.

- backend/controllers/assignmentController.js
  Workflow for Doctor <-> Receptionist staff assignments: sending invitations, accepting/declining
  invitations, and listing linked clinic staff.

- backend/controllers/imageupload.js
  Profile picture upload endpoint. Enforces 5 MB limit, allowed MIME types (JPEG, PNG, WebP),
  magic-byte header signature validation (failing closed on errors), uploads to Cloudinary,
  and updates user's profilePhoto strictly scoped to req.user.accountId.

- backend/controllers/saveuser.js
  Auxiliary helper controller for updating specific user fields.

--------------------------------------------------------------------------------
BACKEND SERVICES, SOCKET & UTILS
--------------------------------------------------------------------------------
- backend/services/queueService.js
  Encapsulates core business logic for queue management: atomic token allocation
  (using DayCounter), state transitions (waiting -> in_consultation -> completed),
  cancelling tokens, and triggering real-time WebSocket broadcast updates.

- backend/services/recordsService.js
  Handles consultation record creation: claims an appointment, ensures a single
  consultation ID entry exists, and links previous consultations across reschedules.

- backend/socket/index.js
  Initializes Socket.IO instance on top of HTTP server, sets CORS rules, authenticates
  connections via cookie/token, and routes clients into authorized doctor/queue rooms.

- backend/socket/identity.js
  Resolves socket connection identity (patient, doctor, or receptionist) and validates
  room subscription authorization.

- backend/socket/access.js
  Validates whether a socket client has rights to join doctor-specific queue rooms.

- backend/socket/emitter.js
  Broadcasts real-time events over Socket.IO (QUEUE_UPDATED, NOW_SERVING_CHANGED) to
  all connected clients in doctor, receptionist, and patient room channels.

- backend/utils/dates.js
  Timezone-aware date utilities for Indian Standard Time (IST). Formats YYYY-MM-DD,
  computes working hour windows, and checks if clinic is open on a given day.

- backend/utils/jwt.js
  Signs JWT tokens with accountId and role. Handles setting secure httpOnly cookies
  and clearing cookies during logout with matching flags (production secure mode).

- backend/utils/sendMail.js
  Nodemailer transporter wrapper for sending transactional emails and OTPs.

- backend/utils/signedUrl.js
  Generates Cloudinary authenticated signed URLs for sensitive medical documents
  (prescriptions, reports, bills) with a 1-hour expiration timestamp.

- backend/routes/route.js
  Central Express router file. Registers all REST API endpoints under /api/v1 for
  auth, profile, search, booking, queue desk, medical records, and socket management.

================================================================================
4. KEY ARCHITECTURAL WORKFLOWS
================================================================================

A. AUTHENTICATION & SESSION PERSISTENCE
   1. User logs in at /login or registers at /register/:role.
   2. Backend verifies credentials/OTP, generates JWT ({ accountId, role }),
      and writes an httpOnly cookie with secure attributes.
   3. On app load, AuthInitialize component fires GET /api/v1/auththroughcookie (/me).
   4. Backend reads the cookie, verifies token, retrieves fresh user document,
      and populates Redux authSlice with user state.

B. DOCTOR DISCOVERY & APPOINTMENT BOOKING
   1. Patient visits /search, searches doctors by specialty or location.
   2. Selects a date; frontend calls POST /api/v1/patient/bookings/checkout.
   3. Backend checks booking window, doctor hours, and opens a Payment record.
   4. Frontend confirms checkout; backend creates Appointment record atomically
      with a sequential tokenNumber using DayCounter and queueService.
   5. Real-time event is broadcasted to the doctor's queue room.

C. REAL-TIME QUEUE MANAGEMENT
   1. Doctor opens /dashboard/doctor/physical; receptionist opens /dashboard/receptionist.
   2. Both clients connect via Socket.IO and join the room `doctor:<doctorId>:<date>`.
   3. Receptionist generates walk-in token -> queueService saves and emits QUEUE_UPDATED.
   4. Doctor clicks "Next Patient" -> appointment status moves from "waiting" to
      "in_consultation". Socket event notifies all waiting patients and receptionist.
   5. Doctor clicks "Complete" -> consultation history is created in Patient document;
      next patient is called.

D. HEALTH RECORDS & ATTESTED CLOUD STORAGE
   1. Receptionist or patient uploads prescription/report/bill via multipart form.
   2. File is validated (magic bytes + MIME type) and uploaded to Cloudinary
      under authenticated private folder.
   3. Document metadata is pushed into the patient's sub-document array.
   4. When accessed, backend generates a signed Cloudinary URL with a 1-hour
      time-to-live (TTL), ensuring protected health documents are never exposed
      via permanent public links.
